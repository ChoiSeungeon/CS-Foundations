# 학습과 평가 규칙

2026-11-04 학습자가 승인한 기본 방식이다. 챕터의 개념과 전체 흐름을 먼저 설명하고, 이후 적용형·면접형 질문으로 확인한다. 기존 초기 진단을 반복하거나 실제 답변 없이 진도를 올리지 않는다.

## 챕터 범위와 필수 과정

챕터는 OS-02처럼 핵심 주제 한 묶음으로 잡는다. 서로 밀접한 ID를 연결할 때는 이번에 다룰 목표와 남길 목표를 명시한다. 한 챕터를 여러 세션에 나눌 수 있다. 질문 수나 시간을 맞추기 위해 핵심 목표를 생략하지 않는다.

모든 핵심 주제에서 다음 과정을 거친다.

1. 챕터 지도: 배우는 이유, 전체 구성, 선수 개념과 이전 내용의 연결, 이번 목표를 먼저 설명한다. 맥락 없이 평가 질문부터 시작하지 않는다.
2. 개념: 정확한 정의·범위·유사 용어의 차이를 먼저 설명한다. 초기 진단 정답도 설명과 확인을 생략하지 않는다.
3. 원리와 예시: 입력·상태·처리·결과를 시각 자료와 구체적 예시로 설명한다. 교사가 한 예시를 끝까지 시연하고 비유·교육 모델·실제 구현을 구분한다.
4. 조건 변화: 설명과 예시 학습 후, 조건을 바꾼 결과 예측과 이유 설명을 학습자에게 요청한다.
5. 원문·실험 확인: 짧은 영어 원문과 한국어 해설로 대조한다. 실험은 확인할 질문이 분명하고 유용한 경우 선택한다. 원문 확인을 적용 질문 이전의 예시 구간에 배치해도 된다.
6. 재설명: 통합 면접형 질문 등으로 자료 없이 본인 말로 설명한다. AI의 시연·수정안·모범 답안은 학습자 증거가 아니다.
7. 간격 복습: 다른 날짜 또는 세션에서 다른 조건·예시로 확인한다.

1~3을 먼저 진행하고 확인 질문 구간을 예고한다. 설명은 소단원으로 나누고 학습자의 자발적인 질문을 받는다. 현재 이해와 선수 개념의 빈 곳은 설명 중 질문이나 이후 적용 답변으로 파악하며, 새 챕터 첫 턴에 진단 문항을 나열하지 않는다. 이미 아는 내용은 속도와 난도를 조절할 수 있지만 필수 과정을 생략하지 않는다.

## 기본 60분 흐름

| 구간 | 계획 시간 | 실제 진행 |
|---|---|---|
| 챕터 지도·이전 내용 연결 | 5분 | 목적·범위·선수 관계와 순서를 안내하고 지난 핵심을 짧게 연결 |
| 개념·원리 학습 | 20분 | 정의·비교·동작 원리를 그림과 일관된 예시로 설명 |
| 예시 시연·원문 확인 | 10분 | 교사가 예시를 끝까지 추적하고 짧은 원문과 대조 |
| 적용형·면접형 확인 | 15분 | 적용형 2~3개와 통합 면접형 1개를 출발점으로 한 질문씩 진행 |
| 마무리·기록 | 10분 | 남은 목표·복습을 정리하고 원문 답변·수정안·진도·정리본을 일괄 저장 |

시간과 문항 수는 계획용 기본값이다. 개념과 예시는 원문 확인과 자연스럽게 연결할 수 있다. 확인되지 않은 목표가 남으면 질문 수를 채웠다는 이유로 완료하지 않고 다음 세션으로 넘긴다. 실제 학습 시간은 학습자가 제공한 경우만 기록한다. 턴 수·달력 경과를 실제 소요 시간으로 바꾸지 않는다.

추가 시간이 가능한 날만 그 범위를 받아 조정한다. 설정·자료 준비·시각화·영어 읽기·실험·기록도 예산 안에 포함한다. 결석분은 의무 분량으로 쌓지 않는다. 큰 실험과 챕터는 여러 세션에 나눌 수 있다.

## 적용형·면접형 질문

- 기본은 큰 적용형 질문 2~3개와 통합 면접형 질문 1개다. 총 3~4개를 출발점으로 삼되 고정 개수로 삼지 않는다. 학습 목표와 실제 답변이 기준이다.
- 적용형은 코드·상태·주소 등의 결과 예측, 조건 변경의 영향과 이유를 묻는다. 충분한 맥락과 가정을 제시하되 질문 앞에 결론을 제공하고 그대로 되묻지 않는다.
- 통합 면접형은 정의·원리·선택 이유·조건을 연결해 설명하게 한다. 직접 고른 프로그램 예시로 개념의 관계를 설명하는 형식을 핵심 단위 마지막에 사용한다.
- 질문 유형과 목적을 예고하고 한 번에 하나만 제시한 뒤 답변을 기다린다. 학습자를 기다리며 다음 질문·진도·평가를 자율적으로 진행하지 않는다.
- 면접형은 답변을 마칠 때까지 기다린 뒤 피드백한다. 학습자가 도움을 요청하면 힌트 흐름을 적용한다. 꼬리 질문은 답변에서 불분명한 부분에 붙인다.
- 답변 구성은 핵심 정의→차이·동작 원리→구체적 예시→적용 조건을 연습한다. 실제 면접 출제나 평가 범위를 단정하지 않는다.
- 챕터 중간에도 해당 소단원 설명을 마친 뒤 면접형 확인을 넣을 수 있다. 배우지 않은 별도 지식을 갑자기 요구하지 않는다.

## 힌트·수정안과 피드백

- 교사의 예시 시연에서는 풀이를 보여준다. 이후 학습자 확인 질문은 조건이나 예시를 바꾸며, 정답·모범 답변은 학습자의 첫 답변 뒤에 제시한다.
- 학습자가 막히거나 모르겠다고 하면 작은 힌트 1회→재시도→설명과 수정안→다른 예시로 확인을 기본으로 한다. 무작정 질문을 이어가거나 학습자가 요청한 설명을 미루지 않는다.
- 맞은 점과 보완할 점을 구분한다. 보완이 필요하면 본인 표현을 살린 2~4문장의 짧은 수정안을 제공하고 추가·변경한 핵심을 짚는다.
- 정확한 답변은 짧게 확인한다. 긴 통합 모범 답변은 주제 정리나 학습자 요청 시 제공하며 AI 작성임을 구분한다.
- 내용 피드백은 정의·원리·가정·조건의 정확성을, 전달 피드백은 핵심을 먼저 말했는지와 설명·예시의 연결을 다룬다. 유창성만으로 개념 이해를 높게 평가하지 않는다.
- 힌트·수정안을 받은 답변과 다른 조건에서 독립적으로 설명한 답변을 구분한다. AI가 보완한 내용을 학습자가 이미 설명했다고 기록하지 않는다.

## 시각 자료와 실험

- 개념 설명에는 내용에 맞는 비주얼을 활용한다. 기본은 핵심 구조도와 단계별 상태 그림 1~2개이며 Mermaid에 한정하지 않는다.
- 구조·영역은 SVG·PNG 도식과 비교표, 시간에 따른 변화는 단계별 그림이나 짧은 애니메이션, 조건 조작이 유용한 경우는 작은 HTML·JavaScript 시뮬레이터, 수치 비교는 그래프를 활용한다. 사용 가능한 도구와 환경에 맞춰 선택한다.
- 처음에는 교사가 시각 자료로 동작을 시연하고 설명한다. 이후 조건을 바꿔 학습자가 예측·조작·해석하도록 한다. 색만으로 구분하지 않고 주소·상태·라벨도 표시한다.
- 교육용 모델의 가정·생략한 조건·실제 구현과의 차이를 표시한다. 시뮬레이터 결과와 실제 OS·JVM·DB 실험 결과를 구분하고 가정값을 실측값처럼 쓰지 않는다.
- 채팅에는 완성된 이미지·표·단계별 그림을 보여준다. 조작형 자료는 실행 가능한 브라우저 등에서 제공하며 채팅 안의 HTML 버튼 실행을 보장하지 않는다.
- 자료 제작과 실행 환경 준비도 시간 예산에 포함한다. 외부 서비스 가입·사이트 공개·플러그인 설치를 기본 수업의 선행 조건으로 추가하지 않는다.
- 시각 자료는 이후 GitHub 정리본과 필요한 Velog 그림에 재사용할 수 있게 원본·가정을 보존한다. 수업 중 필요한 임시 자료 생성과 학습 기록 파일의 중간 갱신을 구분한다.
- 실험은 모든 챕터의 의무가 아니다. 예측→관찰→해석을 수행한 주체와 버전을 명시하고, AI가 실행한 것을 학습자가 실행한 증거로 기록하지 않는다.

## 기록 시점과 형식

수업 도중 노트·원문 답변·진도를 턴마다 수정하지 않고 학습 종료 시 한 번에 기록한다. 학습자의 별도 기록 요청은 해당 범위에서 수행한다. 지금처럼 지침 변경을 명시적으로 요청한 작업은 수업 중 기록과 구분한다.

- 주제 노트: 지도·설명·시연·원문·실제 답변·힌트·수정안·남은 목표를 구분한다.
- 답변 원문: 학습 질문에 답한 모든 메시지와 함께 적은 추가 질문을 순서대로 보존한다. 표현과 오개념을 AI 수정안으로 덮어쓰지 않는다.
- 세션: 계획과 실제 범위, 내용·전달 피드백, 미확인 목표와 다음 행동을 기록한다.
- 정리본: 핵심 개념·시각 자료·예시·출처·복습 질문을 정리한다. 시연 풀이와 학습자 답변을 구분한다.
- 진도·복습·다음 세션은 실제 증거만 반영한다. 정리본 제작·설명 청취·시각 자료 관찰·AI 모범 답안 확인 자체로 상태를 올리지 않는다.

## 복습과 방식 점검

다음 학습 세션·약 1주 뒤·약 3주 뒤를 초기 복습 후보로 둔다. 날짜는 운영상 후보이며 실제 일정·답변에 따라 조정한다. 지나간 분량을 몰아서 수행하지 않는다.

복습도 연결 맥락과 범위를 먼저 안내한다. 회상은 답안이나 정리본을 다시 보여주기 전에 다른 조건으로 확인하고, 부족하면 설명을 보충한다. 갑작스러운 새 챕터 평가 질문과 구분한다. 원래 예시를 숫자만 바꾸어 반복하기보다 조건·대상·실패 상황 등을 바꾼다.

새 방식을 한 챕터에 적용한 뒤 설명의 충분함·질문의 유용성·시각 자료의 효과·준비 시간과 난도를 점검해 조정한다. 전체 목차와 평가 기준은 유지한다.

## 자료와 정확성

수업 전에 실제 해당 절을 읽고, 종료 시 원문 URL·절 제목·확인일·적용 버전을 주제 노트에 남긴다. docs/sources.md는 입구이며 개별 주장의 검증 완료 표시가 아니다. 확인하지 못한 부분은 검증 대기로 남기며 N2 이상으로 올리지 않는다.

짧은 영어 원문과 한국어 해설을 연결한다. 일반 원리부터 설명한 뒤 필요할 때 Java·백엔드 사례로 연결하며, OS·JVM·MySQL 등의 구현·버전 차이를 명시한다. 비유·그림·번역만으로 원문 검증을 대신하지 않고 실제 프로젝트 경험·성능·실험 결과를 추정하지 않는다.
