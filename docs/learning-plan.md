# 학습 진행 계획

## 세션 단위 운영

2026-11-04 승인한 [학습 규칙](study-policy.md)을 따른다. 챕터는 핵심 주제 한 묶음이며 한 세션에 반드시 끝낼 필요는 없다. 지도→개념·원리 설명→교사 시각 자료·예시 시연·원문 확인→적용형·면접형 질문→종료 시 기록 순서로 진행한다. 기본 60분은 지도 5분·개념 20분·예시와 원문 10분·확인 15분·기록 10분이다. 시각 자료와 실험 준비도 포함한다.

다음 OS-09 챕터부터 새 흐름을 시범 적용하고, 끝난 뒤 설명의 충분함·질문 난도·시각 자료 효과·시간을 점검한다. 이전 세션을 새 방식으로 수행했다고 바꾸거나 이 지침 수정만으로 진도를 올리지 않는다.

## 회차 A: 전 범위의 구조 연결

영역 순서: ARCH → OS → DS → NET → DB → JAVA → SE → 혼합 복습. 일차적으로 영역별 지도를 만든다. 한 영역의 모든 세부 주제를 하루에 끝내지 않는다. 영역 안의 주제들이 무엇을 다루고 어떻게 연결되는지 확인하고 대표 주제 1개부터 필수 과정을 진행한다.

8회차는 8일 완강·면접 준비 완료 약속이 아니다. 초기 기본 예산은 8시간이지만 실제 질문·응답에 따라 여러 날로 나눈다. 추가 시간이 있으면 아직 접촉하지 않은 영역을 확인하는 데 먼저 사용하고, 이후 깊이와 실험을 확대한다.

초기 대표 연결: ARCH-03/06, OS-02/09, DS-01/02/05, NET-01/04/12, DB-01/06/09, JAVA-01/04/09, SE-03/06. 이 목록만 배우는 것이 아니다. 해당 영역의 전체 목차를 함께 확인하고 진행하지 못한 항목을 그대로 남긴다. 초기 오답만을 기준으로 선정하지 않았다.

## 회차 B: 기초 전 항목 학습

전체 핵심 목차를 영역별 선수 순서에 따라 순환한다. 주 5개 기본 세션을 계획하고 여유일을 보충·휴식에 사용한다. 매주 최소 2개 영역에 접촉해 한 영역만 장기간 붙잡지 않는다. 모든 항목은 N2 이상을 거치고 조건 변화로 N3에 도전한다. 매주 학습한 것·빈 곳·다음 주제를 확인해 범위가 사라지지 않았는지 점검한다.

기간을 먼저 고정하지 않는다. 첫 5~7개 실제 학습 세션의 시간과 이해도를 기록한 다음 남은 범위의 예상 기간을 갱신한다. 최초 4주에는 범위 접촉·원리 설명·조건 변화·복습의 진행 정도를 평가한다. 4주 완성 목표가 아니다.

## 회차 C: 연결과 확장

핵심을 계속 복습하면서 EXT의 주제를 하나씩 연결한다. ARCH 성능·OS 동기화·NET 전달·DB 정합성을 바탕으로 대용량 처리의 선택과 실패를 설명한다. 확장 주제를 하더라도 미학습 기초 항목을 숨기지 않는다. Java 및 Spring 사용 경험을 일반 CS 이해의 증거로 자동 대체하지 않는다.

## 면접 가능성이 있는 초기 구간

계획 작성일 2026-11-02. 11/5 결과 발표 전에는 회차 A를 진행한다. 통과 시 11/10 면접 전 남은 기본 세션에서 여러 영역의 설명과 프로젝트 질문을 섞고, 미확인 영역을 우선 확인한다. 공개 글과 새 환경 설정은 낮은 우선순위다. 미통과면 같은 목차의 회차 A/B를 계속한다.

미확정 면접을 확정으로 취급하지 않는다. 이후 날짜에 시작하면 현재 상황에 맞게 이 구간을 종료하거나 조정한다. 특정 회사 공고 맞춤은 사용자가 요청할 때만 한다. 지원을 중단하거나 CS 완성을 기다리게 하지 않는다.

## 프로젝트·기록·포트폴리오

주간 복습에서 개념을 본인 프로젝트의 선택·실패·한계에 연결한다. 전체 CS를 프로젝트에 나온 기술만으로 제한하지 않는다. 본인이 구현한 것, 다른 팀원이 한 것, 향후 설계 아이디어, 실험에서 확인한 것을 구분한다.

일상 기록은 짧은 메모로 시작한다. 면접 전에는 Velog 발행 의무가 없다. 이후 2주에 초안 하나를 후보로 두되 실제 시간에 따라 조정한다. AI 답변을 그대로 복사해 이해·검증·실험을 수행한 것처럼 발표하지 않는다.
