# 다른 Codex Cloud 채팅에서 시작하기

## 파일 기반 인계

이 묶음은 이전 대화 없이 읽을 수 있도록 작성했다. 학습자 선호는 learner-context.md, 학습 지침은 루트 AGENTS.md, 실제 진행 상태는 tracking/에 둔다. 원본 포트폴리오나 Windows 절대 경로에 의존하지 않는다.

공식 문서는 [GitHub 저장소 선택과 Cloud 환경 준비](https://learn.chatgpt.com/docs/cloud), [저장소 AGENTS.md 지침](https://learn.chatgpt.com/docs/agent-configuration/agents-md)을 안내한다. 이 구조는 그 기능을 이용해 맥락을 파일로 전달하는 설계다. 이전 채팅의 기억이 자동 전달된다고 가정하지 않는다.

## 최초 연결 순서

1. GitHub에 `cs-study` 같은 이름으로 빈 개인 저장소를 만든다. 공개/비공개는 본인이 선택한다.
2. 이 폴더의 파일들을 저장소 루트에 올린다. `cs-study-starter` 폴더를 한 단계 더 중첩하지 않는다. AGENTS.md와 README.md가 루트에 있어야 한다.
3. GitHub 웹 업로드 또는 기존 Git 도구로 commit·push한다. 개인 채용 정보가 불필요하면 learner-context.md의 해당 절을 제외하고 면접 시점만 새 채팅에 전달해도 된다.
4. Codex Cloud에서 그 저장소와 사용할 브랜치/환경을 선택한다. 계정의 실제 UI와 권한에 따라 연결한다.
5. 첫 수업은 문서만으로 가능하다. Java·DB 실험 직전에 실제 Cloud 환경을 확인한다. 로컬 설치가 Cloud 설치를 뜻하지 않는다.
6. prompts/start-cloud.md의 코드 블록을 새 채팅의 첫 메시지로 붙여 넣는다.

문서 묶음만 다운로드한 상태는 GitHub 연결 완료가 아니다. 이 작업에서 원격 저장소를 생성하거나 push하지 않았다.

## 수업을 이어갈 때

질문은 하나씩 하고 학습자의 답변 후 다음 턴으로 이어간다. 사용 중인 Cloud 진입점에서 대화 방식이 다르면, 현재 질문을 next-session.md에 남기고 다음 작업에 답변을 전달한다. AI가 응답을 대신 만들어 수업을 계속하지 않는다.

수업 종료 시 다음 세션 위치·미응답 질문·복습 항목을 파일로 남긴다. 실행 환경의 임시 파일이나 채팅 안의 설명만으로 인계를 끝내지 않는다. 파일을 수정할 수 없는 모드라면 갱신 내용을 제공하고 반영 여부를 미확인으로 표시한다.

## 두 컴퓨터와 여러 채팅

- 같은 학습 브랜치를 기준으로 최신 파일을 받은 뒤 시작한다. 동시에 같은 진도표를 서로 다른 채팅에서 편집하지 않는 편이 단순하다.
- Cloud 작업 결과가 별도 브랜치나 변경 제안에 있으면 다음 학습이 읽을 브랜치에 실제 반영한 뒤 이동한다.
- 종료할 때 실제 반영된 파일과 아직 반영되지 않은 변경을 구분한다. commit·push·merge는 사용자가 요청한 범위에서 수행한다.
- Git에 반영된 문서·코드는 이동할 수 있지만 DB의 실행 데이터·설치 도구·시크릿은 자동으로 이동하지 않는다. 실험은 초기화 코드로 재현한다.

## 처음에는 하지 않을 일

수업 시작을 위해 별도 서버·배포·CI·유료 서비스·복잡한 DB 구성을 준비하지 않는다. Java 단독, 브라우저 관찰, SQL 실험 중 목적에 가장 간단한 것을 선택한다.
