# 작은 실험

목적에 맞는 가장 작은 환경부터 사용한다. 기존 Java·MySQL·Docker는 활용 후보이며 Cloud 설치 상태는 별도 확인한다. 첫 수업을 위해 모든 도구를 설치하지 않는다.

후보 실험:

| 실험 | 연결 ID | 최소 환경 | 준비·실행·해석 예상 예산 |
|---|---|---|---|
| 배열과 리스트의 접근 경로 추적 | DS-02/03 | 종이 또는 Java | 20~30분, 성능 벤치마크 아님 |
| 해시 충돌과 키의 동등성 | DS-05, JAVA-04 | Java | 30~45분 |
| 공유 카운터의 경쟁 상태 | OS-06, JAVA-11 | Java | 30~60분 |
| DNS·HTTP 관찰 | NET-04/08/12 | 브라우저 도구 또는 사용 가능한 명령 | 20~40분 |
| 인덱스 전후 실행 계획 | DB-06/08 | MySQL의 실험 전용 스키마 | 45~60분 |
| 두 세션의 동시 갱신 | DB-10/11/12 | MySQL 연결 두 개 | 45~60분 |

시간은 계획용 추정이며 설치 문제로 늘어날 수 있다. 15~20분 설정에 막히면 중단 위치를 기록하고 개념 학습으로 전환한다. 큰 실험은 여러 날로 나눈다.

실험 폴더마다 templates/lab.md를 README.md로 사용한다. 초기화 스크립트·실행법·예측·관찰·한계가 있어야 한다. DB 덤프·비밀·대형 바이너리는 저장소에 넣지 않는다. 성능 측정에는 warmup·반복·조건 통제가 필요하므로 짧은 예시의 단발 시간으로 일반적인 속도를 주장하지 않는다.
