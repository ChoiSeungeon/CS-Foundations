## 현재까지 확인한 학습자 답변

이 채팅에서 받은 답변이며 초기 진단을 옮겨 적은 것이 아니다.

1. 저장과 실행의 차이: “SSD에서 실행시킬 프로그램을 RAM에 로드하고 CPU가 해당 프로그램을 실행시키는데 필요한 연산을 진행합니다.” 기본 흐름을 확인했다. 프로그램 전체를 한꺼번에 로드할 필요는 없다는 설명은 AI가 제공했으며 학습자의 재설명은 아직 없다.
2. RAM을 사용하는 이유: “SSD에 있는 데이터를 곧바로 CPU에서 사용할려면 상대적으로 시간이 많이 걸리기 때문입니다.” 접근 지연 차이를 설명했다. 일반적인 PC에서 저장장치 I/O와 메모리 접근의 방식이 다르다는 부분은 별도 확인이 필요하다.
3. RAM만으로 보관할 때의 문제: “RAM은 휘발성 저장매체이기 때문에 영구적으로 데이터를 저장할 수 없고 RAM이 SSD보다 가격이 비싸기 때문에 추가 비용이 발생할 수 있습니다.” 휘발성과 비용을 설명했다. 비용 비교는 같은 용량 기준이라는 피드백을 제공했다.
4. CPU 내부 저장 공간: “L1, L2 캐시가 있습니다. 해당 공간은 RAM에서 CPU로 데이터를 전달하는 시간을 단축하기 위해 사용하며 RAM에서 자주 접근하는 데이터를 로드하여 데이터 로딩 시간을 단축합니다.” 캐시의 기본 목적을 설명했다. 캐시를 언급했다는 이유로 레지스터를 모른다고 판정하지 않는다. 레지스터와 캐시의 구분, 캐시 라인과 지역성은 아직 학습자 답변으로 확인하지 않았다.

## 이후 질의응답과 교정

- RAM의 A만 3에서 10으로 바꾸고 R1=3, R2=5를 유지한 예시에서 학습자는 결과가 8이며 R1과 R2의 값이 근거라고 설명했다. RAM 변경이 이미 읽은 레지스터에 자동 반영되지 않는 예시를 확인했다.
- 명령과 데이터 구분: 같은 3과 5로 곱셈을 하려면 “연산 명령이 바뀌어야 합니다. 두 숫자 그대로 3과 5를 사용하기 때문입니다.”라고 답했다.
- 읽기 요청에서 주소 필요 여부를 질문했다. 주소와 읽기 요청을 CPU가 보내고 RAM이 데이터를 반환한다고 설명한 뒤, 학습자는 “읽어올 수 있습니다. CPU는 주소 200에 있는 값을 읽기 요청을 합니다.”라고 답했다.
- 읽기·계산·쓰기 전체 재설명에서 RAM이 저장할 주소를 응답한다고 혼동했다. CPU가 목적 주소도 지정한다고 교정했다. 이후 다른 목적 주소에 대해 “주소 400에 데이터 8을 제어 정보 쓰기로 요청합니다.”라고 답했다. 교정한 쓰기 요청은 확인했지만 전체 흐름을 다시 설명한 것으로 확대 판정하지 않는다.
- ARCH-06의 시간·공간 지역성 설명과 학습자 답변은 [해당 노트](ARCH-06-memory-hierarchy.md)에 이어 기록했다.
- 추가 질문: CPU의 쓰기 요청 뒤 RAM의 응답이 없는지 질문했다. 앞선 교육용 흐름에서 응답을 생략했음을 밝히고, 실제 응답 방식은 연결 규약과 계층에 따라 달라진다고 설명했다. AXI의 쓰기 응답 사례를 제공했다. 설명 청취를 이해 확인으로 기록하지 않는다.
- 사진 편집 통합 예시에서 SSD의 보존·비용·용량 역할, RAM 로딩, 반복 접근을 위한 캐시, CPU가 사용할 값을 레지스터에 보관하는 역할을 연결해 설명했다. 레지스터가 값을 보관하고 ALU가 연산한다는 구분은 최종 피드백으로 보충했다. 사진 답변의 원문은 [ARCH-06 노트](ARCH-06-memory-hierarchy.md)에 보존했다.

## 원문 확인

확인일: 2026-11-03(Asia/Seoul). 웹 열람 도구로 직접 읽었다. 자료는 Chris Terman의 6.004 교육용 설명이며, 아래의 예시는 교육용 CPU 모델을 기준으로 한다. 자료의 지연 시간 수치·레지스터 개수 등을 현재의 모든 CPU에 적용하지 않는다.

- [L09: Instruction Set Architectures](https://computationstructures.org/lectures/isa/isa.html): 폰 노이만 모델, 명령과 데이터, 레지스터·ALU·주기억장치 설명 단락. CPU는 연산할 값을 임시 레지스터로 읽어 오고, ALU 결과를 레지스터에 보관하며 메모리와 데이터를 주고받는 구조를 확인했다.
  - 짧은 원문: “The CPU will read these values into its temporary registers”
  - 한국어: CPU는 이 값들을 임시 레지스터로 읽어 들인다.
- [L14: The Memory Hierarchy](https://computationstructures.org/lectures/caches/caches.html): 도입부의 메모리 기술 비교, SRAM·DRAM의 전원 의존성, 지역성 및 캐시 hit/miss 설명 단락. 레지스터의 작은 용량과 짧은 접근 지연, SRAM·DRAM의 휘발성, 플래시의 비휘발성, 최근 접근한 블록의 캐싱과 다단계 캐시의 역할을 확인했다. 특정 제품의 최신 가격이나 성능 수치는 확인하지 않았다.
- CS50 접속 경로 문제와 해결한 열람 경로: [출처 사용법](../docs/sources.md#원문-접속-경로와-장애-확인).
- 추가 1차 자료: [Arm, Introduction to AMBA AXI4](https://developer.arm.com/-/media/Arm%20Developer%20Community/PDF/Learn%20the%20Architecture/102202_0100_01_Introduction_to_AMBA_AXI.pdf), 문서 102202, Issue 01, 2020. 확인일 2026-11-03. §5.1 Write channel signals, §5.5 Cache support, §5.6 Response signaling을 읽었다. AXI의 별도 Write Response 채널과 응답 상태를 확인했다. 중간 구성 요소가 응답할 수 있는 경우도 있으므로 응답을 실제 DRAM 셀의 기록 완료와 일률적으로 동일시하지 않는다. AXI 연결 규약의 예시이며 모든 RAM 칩의 직접 인터페이스가 AXI라고 일반화하지 않는다.

AI의 원문 대조와 학습자가 원문을 읽고 이해한 증거는 구분한다. 원문 열람 성공만으로 진도를 올리지 않는다.

## 남은 목표

- 버스의 읽기·쓰기 요청을 교정한 뒤 전체 흐름을 새로운 예시에서 다시 설명하기.
- 레지스터의 값 보관과 ALU의 연산 역할을 구분해 재설명하기.
- 실제 규약별 쓰기 응답과 교육용 추상화의 구분. AXI 신호 암기를 요구하지 않는다.
- 별도 세션에서 조건을 바꾼 복습. 아직 N4 근거는 없다.
- ARCH-04의 명령 실행, ARCH-07의 캐시 정책은 해당 주제에서 이어간다.

기본 역할과 교정 후의 읽기·쓰기 요청을 확인한 근거로 N2를 기록한다. 교정한 전체 흐름의 독립 재설명과 간격 복습은 아직 확인하지 않았으므로 N3·N4로 올리지 않는다.
