## 정의와 실제 수업 범위

프로그램은 저장된 명령과 데이터이며, 프로세스는 이를 실행한 인스턴스로 메모리와 열린 파일 등 자원을 관리하는 단위다. 스레드는 프로세스 안의 실행 흐름이다. 같은 프로세스의 스레드는 주소 공간을 함께 사용하지만 PC·레지스터 상태와 함수 호출 스택을 따로 유지한다.

한 코어에서 번갈아 실행하면 실행 흐름별 상태를 저장·복원한다. 이는 각 실행에 물리적 CPU 레지스터를 영구히 따로 배정한다는 뜻이 아니다. PC 상태가 독립적이어도 숫자 값은 같을 수 있다.

## AI가 제공한 짧은 수정안

메신저 실행파일은 프로그램이고 이를 실행한 인스턴스가 프로세스다. 교육용 설계로 프로세스 하나에 송신·수신 스레드를 두면 코드와 대화 상대 정보 등을 함께 사용할 수 있다. 각 스레드는 PC·레지스터 상태·스택을 따로 유지한다. 수신이 기다리는 동안 송신 작업이 준비되면 OS가 필요한 실행 상태를 전환해 송신을 실행할 수 있다.

이 문단과 텍스트 편집기 모범 답변은 AI 작성이다. 특정 실제 앱의 구현 사실이나 학습자의 독립 설명 증거가 아니다. 서로 다른 메시지라는 사실만으로 지역변수·공유 객체 여부를 판정하지 않는다.

## 원문 확인

- [OSTEP Chapter 4: The Abstraction: The Process](https://pages.cs.wisc.edu/~remzi/OSTEP/cpu-intro.pdf), Version 1.10, 도입·§4.1. 확인일 2026-11-03. 프로그램과 실행 인스턴스, 메모리·레지스터·열린 파일 등의 상태를 읽었다.
- 수업에 제시한 짧은 원문: “a process is simply a running program”. 한국어: 프로세스는 실행 중인 프로그램이다.
- [OSTEP Chapter 26: Concurrency: An Introduction](https://pages.cs.wisc.edu/~remzi/OSTEP/threads-intro.pdf), Version 1.10, 도입·Figure 26.1·§26.1. 확인일 2026-11-03, 재확인 2026-11-04. 주소 공간 공유와 스레드별 PC·레지스터·스택, 병렬 처리와 I/O 대기의 활용을 읽었다.
- 수업에 제시한 짧은 원문: “more than one point of execution”. 한국어: 여러 실행 지점. 학습자가 이를 읽었다는 사실과 스스로 설명한 증거를 구분한다.
- [GCC 온라인 매뉴얼, §3.11 Options for Debugging Your Program](https://gcc.gnu.org/onlinedocs/gcc/Debugging-Options.html). 확인일 2026-11-04. 최적화로 선언한 변수가 실제 코드에서 사라질 수 있음을 확인했다. 설치된 GCC 버전이나 실제 생성 코드를 확인한 것은 아니다.

## 상태와 남은 목표

기본 원리와 여러 조건의 결과·이유 설명, 원문 확인을 근거로 N2로 기록한다. N3로 올리기 전 프로그램·프로세스·스레드의 관계와 자원 소유를 빠짐없이 본인 말로 연결하는 재설명을 확인한다. 열린 파일 등 공유 자원의 범위도 예시로 보완한다. N4에 필요한 이후 세션의 간격 복습은 아직 없다.

스레드별 스택도 같은 프로세스의 주소 공간에 있다는 점, 공유 데이터의 접근 순서 조정은 후속 보완 범위다. 스택이 별도라는 이유로 프로세스 간 메모리 보호와 동일하다고 일반화하지 않는다. 의사코드의 참조 복사를 Java 전달 규칙 전체의 검증으로 취급하지 않는다.
