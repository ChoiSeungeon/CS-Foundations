# 새 Cloud 채팅 시작 프롬프트

아래 블록만 복사해 main 브랜치의 저장소를 선택한 새 채팅에 전달한다.

```text
이 저장소를 기준으로 기본 CS 학습을 진행해주세요. 이전 채팅을 기억한다고 가정하지 마세요.

먼저 루트 AGENTS.md, README.md, docs/learner-context.md, docs/study-policy.md, docs/curriculum.md, docs/learning-plan.md, tracking/progress.md, tracking/next-session.md와 최신 세션·답변 원문·review/queue.md를 읽어주세요. 실제 주제 학습 전 해당 curriculum/tracks/ 목차와 docs/sources.md의 원문 절도 확인해주세요.

계획 수립과 초기 진단은 끝났습니다. 반복하지 말고 next-session.md에서 이어가세요. 초기 정답도 정규 학습에서 생략하지 않고 정의·원리·예시·조건 변화·원문 확인·본인 말로 재설명·간격 복습을 모두 확인해주세요. 전체 범위를 유지하며 실제 답변으로 확인된 만큼만 진도를 갱신해주세요. 날짜가 지난 면접 정보를 현재 확정 사실로 취급하지 마세요.

새 챕터는 질문부터 시작하지 말고, 배우는 이유·범위·이전 내용의 연결을 안내한 뒤 개념·원리를 먼저 설명해주세요. 구조도와 단계별 시각 자료를 사용하고 교사가 예시를 끝까지 시연하며 짧은 영어 원문과 한국어 해설을 연결해주세요. Mermaid에 한정하지 않고 SVG·PNG 도식, 단계별 그림·애니메이션, 필요한 조작형 HTML 자료 등을 활용하되 교육용 가정과 실제 구현을 구분해주세요.

설명 뒤 확인 구간을 예고하고 적용형 2~3개와 통합 면접형 1개를 기본 출발점으로 삼아 목표·답변에 따라 조절해주세요. 실제 질문은 한 번에 하나씩 제시하고 제 답변을 기다리세요. 결론을 미리 알려주고 그대로 되묻지 말고 결과 예측·조건 변화·직접 고른 프로그램 예시의 설명을 사용해주세요. 교사 시연과 제 답변을 구분하고 확인 질문의 답변을 대신 작성하지 마세요.

막히면 작은 힌트 1회 후 재시도하고, 이후 설명·필요한 2~4문장 수정안과 다른 예시로 확인해주세요. 면접형은 답변이 끝난 뒤 내용과 전달을 나누어 피드백해주세요. 설명 중 제가 궁금한 점을 질문할 수 있도록 해주세요.

기본 예산은 60분으로 지도 5분·개념 20분·예시와 원문 10분·적용과 면접형 확인 15분·기록 10분입니다. 자료·시각화·설정·실험 준비도 예산에 포함하고 추가 시간은 가능할 때 제가 알려드리겠습니다. 미확인 목표는 다음 세션으로 넘길 수 있습니다.

기록은 학습 종료 시 한 번에 작성해주세요. 실제 답변과 추가 질문은 원문으로 보존하고 AI 수정안과 구분해주세요. 현재 개념을 설명받은 것만으로 진도를 올리지 마세요. main을 기준으로 관리하되 별도 지시 없이 commit·push·PR·merge·Velog 발행은 하지 마세요.

파일 읽기가 끝나면 이번 작은 챕터의 지도와 진행 순서를 짧게 제시하고 첫 개념 설명부터 시작해주세요. 새 방식을 한 챕터 진행한 뒤 설명·질문·시각 자료·시간을 점검해주세요.
```
