# 초기 표본 진단 기록

기록일 2026-11-02. 계획 수립 대화에서 나온 답변의 요약이다. 이 저장소에서 학습을 수행하거나 복습을 통과했다는 증거가 아니다. 모든 연결 주제의 정규 학습 상태는 N0다. 정답은 생략 허용이 아니라 이후 예시·속도 조절의 참고다.

| 항목 | 학습자 답변의 요지 | 관찰과 추후 확인 | 연결 ID |
|---|---|---|---|
| 프로세스·스레드 | 프로세스는 프로그램 단위, 한 스레드 안에 여러 프로세스가 있다고 생각 | 포함 관계 혼동. 자원·공유·실행을 다시 학습 | OS-02 |
| 인덱스 정의 | DB에서 정하는 번호, 빠른 검색 용도 | 목적 기억. 자료구조·접근 경로 보완 | DB-06 |
| URL 입력 흐름 | DNS로 도메인에 대응하는 IP를 얻음 | DNS 역할 일부 설명. 캐시·연결·HTTP·보안·표현 과정 미확인 | NET-04, NET-12 |
| 배열·리스트 | 배열은 연속, 리스트는 데이터와 다음 위치 저장 | 저장 구조 설명. 연산 조건·참조 배열의 의미 추가 확인 | DS-02, DS-03 |
| CPU 캐시 | 저장장치 데이터를 RAM에 빠르게 올리기 위한 캐시라고 설명 | 계층 혼동. CPU와 RAM 사이 역할 보완 | ARCH-06, ARCH-07 |
| ==·equals | 동일 객체 확인과 클래스 정의에 따른 내용 비교 | 기본 구분 설명. 기본형·Object 기본 동작·hashCode 계약은 학습 필요 | JAVA-04 |
| 트랜잭션 | 작업 단위와 롤백·완료 구분 | 기본 경계 이해. ACID·격리·외부 자원 범위 추가 학습 | DB-09 |
| 인증·인가 | 누구인가 확인, 접근이 올바른지 판단 | 기본 방향 이해. 자원·작업별 권한으로 구체화 | SE-06 |
| TCP·UDP | 연결·비연결로 구분 | 용어 기억. 전달 단위·보장·제어 원리 학습 필요 | NET-05 |
| 교착상태 | 각 작업이 상대가 보유한 자원을 기다려 진행 불가 | 대표 상황 설명. 락·필요 조건·대응 학습 필요 | OS-08 |
| 단위·통합 테스트 | 한 모듈 확인과 여러 모듈 연결 확인 | 기본 구분 설명. 검증 대상·실제 의존성으로 재확인 | SE-03 |
| 모든 컬럼 인덱스 | 좋지 않다고 판단하나 이유 설명 어려움 | 유지 비용과 조회 패턴 보완 | DB-06, DB-07 |
| 스레드 수 증가 | 의존 작업은 병렬화되지 않음, 문맥 교환 고려 | 조건·근거 설명. I/O·락·풀·병목 연결은 학습 필요 | ARCH-08, OS-03, JAVA-12 |
| 해시 조회 | 모름 | 기본 원리 학습 필요 | DS-05 |
| 트랜잭션 두 개의 잔액 변경 | 항상 방지 못함, 미완료/롤백 시 잘못 읽을 수 있음 | 위험 인식. dirty read와 lost update·격리 수준 구분 보완 | DB-10, DB-11 |
| 가상 메모리 | 모름 | 주소 공간·주소 변환·보호부터 학습 | OS-09, OS-10 |

계획 대화에서 짧은 교정을 들었지만 재설명·조건 변화·복습이 검증된 것은 아니다. 특정 영역 전체가 약하거나 강하다고 일반화하지 않는다.
