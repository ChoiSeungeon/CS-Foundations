## 01. SSD에 저장된 프로그램과 실행 중 구성 요소의 역할

질문 맥락: 프로그램이 저장되어 있을 때와 실행 중일 때 CPU·RAM·SSD의 역할.

> SSD에서 실행시킬 프로그램을 RAM에 로드하고 CPU가 해당 프로그램을 실행시키는데 필요한 연산을 진행합니다.

## 02. RAM을 사용하는 이유와 원문 검증 대기 질문

질문 맥락: SSD의 프로그램을 실행할 때 RAM을 사용하는 이유.

> SSD에 있는 데이터를 곧바로 CPU에서 사용할려면 상대적으로 시간이 많이 걸리기 때문입니다.
> 추가로 "원문은 현재 연결 문제로 확인하지 못해 검증 대기로 남기겠습니다." 이게 무슨 말인가요?

## 03. RAM만으로 보관할 때의 문제와 CS50 접속 요청

질문 맥락: 빠른 RAM만 사용하고 SSD를 없앨 때의 문제.

> RAM은 휘발성 저장매체이기 때문에 영구적으로 데이터를 저장할 수 없고 RAM이 SSD보다 가격이 비싸기 때문에 추가 비용이 발생할 수 있습니다.
> 추가로 CS50 강의 노트에 접속이 안되는 이유를 찾아서 해결해줘 일시적인 접근 불가라고 보기엔 계속 접속안될거 같아

## 04. CPU 내부 저장 공간

질문 맥락: CPU 내부에서 값을 잠시 보관하는 공간에 대한 현재 이해.

> L1, L2 캐시가 있습니다. 해당 공간은 RAM에서 CPU로 데이터를 전달하는 시간을 단축하기 위해 사용하며 RAM에서 자주 접근하는 데이터를 로드하여 데이터 로딩 시간을 단축합니다.

## 05. 이미 레지스터에 있는 값의 재사용

질문 맥락: 3과 5가 레지스터에 유지되면 덧셈을 다시 할 때 RAM에서 반드시 다시 읽어야 하는지.

> 이미 레지스터에 해당 값들과 해당 값들을 사용한 연산의 결과 값들이 저장되어 있으므로 반드시 RAM에서 다시 읽을 필요는 없습니다.

## 06. RAM만 변경한 뒤 레지스터로 계산

질문 맥락: R1=3, R2=5를 유지하고 RAM의 원래 위치만 10으로 바꾼 뒤 R3에 R1+R2를 계산한 결과.

> 8이 들어갑니다. R1에는 3, R2에는 5가 들어가 있기 때문입니다.

## 07. 쓰기 요청의 주소·데이터·제어 정보

질문 맥락: RAM 주소 200에 값 8을 기록할 때 전달하는 정보.

> 주소 200, 데이터 8, 제어 정보 쓰기

## 08. 프로그램 실행과 구성 요소의 협력 설명

질문 맥락: SSD의 덧셈 프로그램을 실행해 3과 5를 더하고 RAM에 결과를 기록하는 흐름.

> SSD에 사용할 3과 5가 저장되어 있으므로 3과 5를 RAM에 로딩하고 버스를 통해 결과를 저장할 RAM의 주소와 3과 5, 어떤 행동을 할지를 CPU에 전달합니다. 전달 받은 CPU는 내부의 레지스터에 3과 5, 연산 이후의 결과를 저장하고 다시 저장된 결과 값은 RAM에 기록됩니다.

## 09. 같은 데이터로 다른 연산을 수행하는 조건

질문 맥락: 같은 3과 5로 덧셈 대신 곱셈을 할 때 바뀌어야 하는 것.

> 연산 명령이 바뀌어야 합니다. 두 숫자 그대로 3과 5를 사용하기 때문입니다.

## 10. 읽기 요청과 주소의 필요성

질문 맥락: RAM 주소 100의 값 3을 R1으로 읽어 오는 요청·응답 순서.

> 버스를 통해 데이터 3을 읽기 요청을 하고 RAM은 3을 전달합니다.
> 그러면 추가로 궁금한게 이런 경우에는 주소는 필요없고 데이터와 제어정보만 전달하는건가?

## 11. 값을 몰라도 주소로 읽을 수 있는지

질문 맥락: CPU가 주소 200의 값을 모르는 상황에서 읽기 요청 가능 여부.

> 읽어올 수 있습니다. CPU는 주소 200에 있는 값을 읽기 요청을 합니다.

## 12. 읽기·연산·쓰기 전체 흐름과 명령 전달 질문

질문 맥락: RAM 주소 100의 3과 주소 200의 5를 더해 주소 300에 기록하는 순서.

> 먼저 CPU가 주소 100과 주소 200에 있는 값을 읽기로 버스를 통해 요청하고 RAM은 해당 요청으로 인해 버스를 통해 3과 5를 CPU에 전달합니다. 값을 전달 받은 CPU는 3과 5를 레지스터에 잠시 저장하고 결과 값 8 또한 레지스터에 잠시 저장합니다. 그 이후 CPU는 RAM에게 주소 8이라는 값을 버스를 통해 쓰기 요청하고 RAM은 값을 저장할 주소인 300을 응답하고 RAM에 8을 기록합니다.
>
> 지금 추가로 궁금한 것은 그러면 덧셈을 하라는 명령은 언제, 어떻게 누구에게 전달되냐 입니다.
> 또한 "그 이후 CPU는 RAM에게 주소 8이라는 값을 버스를 통해 쓰기 요청하고 RAM은 값을 저장할 주소인 300을 응답하고 RAM에 8을 기록합니다." 해당 부분이 맞는지 의문입니다.

## 13. 교정 후 다른 주소에 쓰기

질문 맥락: 결과 8을 RAM 주소 400에 기록할 때 CPU가 전달하는 정보.

> 주소 400에 데이터 8을 제어 정보 쓰기로 요청합니다.

## 14. 시간 지역성과 쓰기 응답 질문

질문 맥락: 같은 주소를 100번 읽는 A와 서로 다른 주소 100곳을 한 번씩 읽는 B의 시간 지역성 비교.

> A입니다. 해당 값을 이미 반복해서 100번 읽었으므로 가까운 시간 내에 다시 해당 값을 읽을 가능성이 크기 때문입니다.
>
> 추가로 이전 내용에서 CPU가 쓰기 요청을 보내면 RAM은 따로 응답을 하지는 않는 것인가요?

## 15. 가까운 주소 접근과 캐시

질문 맥락: 100, 104, 108, 112처럼 가까운 주소를 읽을 때 캐시가 도움이 될 수 있는지.

> 도움이 될 수 있습니다. 서로 가까이 있는 공간에는 서로 연관된 정보가 저장되어 있을 수 있기 때문입니다.

## 16. 연속 접근의 캐시 라인 가져오기 횟수

질문 맥락: 교육용 16바이트 라인, 빈 캐시, 미리 읽기와 교체가 없는 조건에서 32→36→40→44→48을 읽기.

> 2번 가져옵니다.
> 공간 지역성에 의해 32를 가져올 때 32~47을 함께 가져오기 때문입니다.

## 17. 라인 간격 접근에서 공간 지역성의 이득

질문 맥락: 같은 조건에서 32→48→64→80→96을 각 한 번씩만 읽고 끝내는 경우.

> 해당 과정으로 인해 공간 지역성으로 얻는 이득은 없습니다. 각각 주소를 읽을 때 라인 단위로 가져오지만 그 라인에는 다음으로 읽는 주소가 포함되어 있지 않아 다시 읽어드려야하기 때문입니다.

## 18. 캐시를 RAM만큼 크게 만들기 어려운 이유

질문 맥락: 빠른 캐시의 용량을 크게 늘려 RAM을 대체하는 것의 제약.

> 용량 대비 비용이 캐시가 RAM에 비해 비싸기 때문입니다.

## 19. 여러 메모리 계층을 함께 사용하는 이유

질문 맥락: 레지스터·캐시·RAM·SSD를 함께 사용하는 이유를 본인 말로 설명.

> 각각의 데이터에 따라 데이터를 사용하는 시점에 따라 영구적으로 저장되어야 하는 데이터, 휘발되어도 괜찮은 데이터가 구분이 되고 빠르게 접근해야해서 효율을 극대화 시켜야하는 데이터 빠른 접근보다 비용을 고려해야하는 데이터 등 각각의 데이터의 특성에 따라 가장 적합하게 사용하기 위해서 입니다.

## 20. 레지스터만 변경한 조건과 수정 답안 요청

질문 맥락: SSD와 RAM에 100이 있고 레지스터만 110으로 바꾼 뒤 RAM 쓰기와 파일 저장을 하지 않은 경우.

> 저장하는 동작을 하지 않았기 때문에 RAM과 SSD에는 여저힌 100이라는 값이 저장되어 있습니다.
>
> 추가로 이전 답변의 모범 답안 혹은 저의 답변에서 수정한 내용도 보여주세요.
> 이것은 추후 학습에도 적용할지 고민입니다.

## 21. 다른 예시에서 시간·공간 지역성 구분

질문 맥락: 연속된 네 배열 요소를 같은 순서로 읽는 동작을 10번 반복할 때의 지역성.

> 시간 지역성은 10번 반복하는 동작에서 나타나고 공간 지역성은 연속된 네 요소를 읽는 동작에서 나타납니다.

## 22. 사진 편집에서 여러 계층의 역할 통합

질문 맥락: SSD 사진 파일의 같은 부분을 반복 편집할 때 속도·용량·비용·보존과 각 계층의 역할 설명.

> 사진 파일 자체는 비교적 용량이 크고 영구적으로 데이터 보존이 되어야하는 데이터이기 때문에 평소에는 데이터를 보존할 수 있고 용량대비 비용이 적은 SSD에 저장되어 있고 이 사진을 편집하기 위해서 RAM에 로딩합니다. 그리고 해당 사진에서 같은 부분을 여러번 편집하기 때문에 접근 속도를 높이기 위해 캐시에 해당 부분을 저장합니다. 마지막으로 해당 사진의 편집되는 부분을 cpu가 사용하기 위해 cpu 내부의 레지스터에 저장되고 연산됩니다.
